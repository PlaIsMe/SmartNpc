# Minecraft 1.21.11 port

The `1.21.11` branch targets Minecraft 1.21.11, NeoForge 21.11.48, Java 21, ModDevGradle 2.0.147 and Gradle 9.2.1 with official Mojang mappings. The user's existing mod version `2.0.0` is preserved.

The API migration reuses applicable changes from the local 26.1.2 branch, adapted to actual 1.21.11 sources. Entity persistence uses ValueInput/ValueOutput, shared UUID helpers preserve the four-int-array encoding, and SavedDataType IDs retain the original DATA_NAME filenames. Profiles use the new Authlib APIs, with profile application still scheduled on the server thread. Tool/armor classification uses tags/components, item definitions use the new items directory, and reload listeners use codecs.

Rendering uses AvatarRenderState and SubmitNodeCollector. FakePlayerRenderState keeps the custom renderer selected when Minecraft routes avatar states, and inspector mixins target current submit/camera/packet-listener methods. Boat passenger rejection targets AbstractBoat, where the override now lives. Chunk ownership inspection uses TicketStorage and NeoForge TicketController accessors. Protocol remains 8 from the 1.21.1 branch; payload layout is unchanged.

Epic Fight and Yes Steve Model dependencies, implementations, registration, configuration, mixins, synchronized flags, emote goal and Epic Fight animation assets are removed. Legacy YSM roster entries are ignored during parsing so identities can still load. The separate Minecraft instance config files were not modified.

Better Combat remains optional. Development runtime pins Better Combat 3.1.0+1.21.11, Cloth Config 21.11.153 and Player Animation Library 1.1.11. Only PAL is needed on the compile classpath; external animation types remain behind Better Combat's client gate. PlayerAnimationSampler uses the PAL 1.1.x bone getters and transform order. None of these optional mods are bundled in the jar or declared required.

Validation on 2026-11-03:

- `compileJava` and `assemble` pass using Java 21. No tests were added or run.
- The client starts, reloads resources and shuts down cleanly with the optional development mods installed.
- The client also starts and reloads resources with all localRuntime dependencies removed.
- Isolated startup directories and logs live under `build/porting`. No existing worlds or instance configurations were used.
- A dedicated-server `--initSettings` bootstrap reaches settings generation; NeoForge reports a missing server thread on that intentional early exit. A running dedicated world was not validated.
- NPC spawning, rendering in a world, AI behavior, inspector interaction and combat still require gameplay validation. Client startup does not establish those behaviors.

`assemble` writes `SmartNpc-1.21.11-2.0.0.jar` to the existing `C:/Users/Admin/Desktop/Minecraft/delivery` destination.
